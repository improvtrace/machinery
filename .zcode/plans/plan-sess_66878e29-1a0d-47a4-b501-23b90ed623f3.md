# Machinery 项目精简重构计划

## Context

当前项目是 machinery 任务队列库的 fork，包含 v1 + v2 两套代码、多种 broker/backend 实现（amqp/sqs/gcppubsub/dynamodb/memcache/mongo/redis/eager/null）、完整的 Makefile/Docker/CI 构建链和大量测试。目标是精简为一个**只保留 redis 实现、所有代码平铺在项目根目录单一 package** 的库（分支 `feat/unified_redis_client` 上的后续工作基础）。

已确认的决策：
- Redis 仅保留 **go-redis v9** 变体（删除 redigo 版）
- module 路径改为 `github.com/RichardKnop/machinery`（去掉 `/v2`）
- examples 一并删除

## 1. 删除构建 / CI 相关（根目录）

`Makefile`、`Dockerfile.gcppubsub`、`Dockerfile.test`、`docker-compose.test.yml`、`wait-for-it.sh`、`.travis.yml`、`.deepsource.toml`

## 2. 删除测试相关

- 根目录：`integration-tests/`、`example/`、`instruction-notes/`
- v2 内所有 `*_test.go`（约 33 个）、`v2/integration-tests/`、`v2/example/`
- `v2/config/test.env`、`v2/config/testconfig.yml`（测试 fixture）

## 3. 删除 v1

整个 `v1/` 目录。

## 4. 仅保留 redis 实现

删除：
- `v2/brokers/{amqp,eager,gcppubsub,sqs}`、`v2/brokers/iface/sqs`、`v2/brokers/package.go`
- `v2/backends/{amqp,dynamodb,eager,memcache,mongo,null}`、`v2/backends/iface/dynamodb`、`v2/backends/package.go`
- `v2/locks/eager`
- redigo 变体：`v2/brokers/redis/redis.go`、`v2/backends/redis/redis.go`
- 死代码：`v2/common/amqp.go`；`config` 里的 `AMQPConfig/SQSConfig/DynamoDBConfig/GCPPubSubConfig/MongoDBConfig/QueueDeclareArgs/QueueBindingArgs` 及其 import；`utils.GetPureUUID`、`utils.DeepClone`；`common/redis.go` 中 redigo 的 `RedisConnector/NewPool/open/defaultConfig`（go-redis 变体只用 `NewGoRedisClient`）
- AMQP 残留逻辑：`worker.go` 删除 `hasAMQPBackend()` 与 `backends/amqp` import（`taskSucceeded` 中该分支只对 AMQP 做延迟 purge，redis 行为保持不变，直接去掉分支）；`async_result.go` 的 `Touch()` 删除 AMQP purge 块；`IsAMQP()` 从 Backend 接口与 BaseBackend 中移除

## 6. 合并 package 修正

- 去掉限定符：`tasks.` `config.` `log.` `utils.` `tracing.` `retry.` `common.` `errs.` `iface.` `result.` `brokersiface.` `backendsiface.` `lockiface.`（约 300 处，集中在 `server.go`、`redis_broker.go`、`redis_backend.go`）

- 依赖冲突已排查：仅上述列出的 7 组标识符冲突，无 init() 冲突，方法接收者类型互不冲突
